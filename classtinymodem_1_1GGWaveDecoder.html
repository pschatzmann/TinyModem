Detailed Description

ggwave compatible demodulator: the PCM audio data is written to the decoder and the payload of the received messages is written to the output. The input can be 8, 16 or 32 bit signed samples with any number of channels (only GGWaveConfig::channel is evaluated).

All ggwave tones are multiples of the frame rate, so they are periodic in a frame. The decoder calculates a DFT of the used bins for each quarter frame (block) and adds the blocks coherently. For each window of one frame a marker score is calculated: the sum of (on - off) / (on + off) of the 16 tone pairs of the marker, which is +16 for the start marker, -16 for the end marker and about 0 for noise and data. When the start marker was detected, the position with the highest sum of the scores over the length of the marker provides the start of the data. Then each symbol is decoded by adding the power of the windows inside the symbol (without the first and last block). The power is not added coherently over the whole symbol (like ggwave), so a different clock of the sender is tolerated. This is done in parallel for the normal, fast and fastest variant (rx_any_speed) and for the timing offsets -1, 0 and +1 block. The first candidate with a valid Reed-Solomon code and the end marker at the expected position wins.

Unlike ggwave, which records the audio of a whole message, the memory needed is small: about 27 KB for the audible protocols at 48000 Hz (23 KB at 24000 Hz).
